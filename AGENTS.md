# Ramcar Spend Flow — agent notes

A real Laravel 13 + Filament 5 + Livewire 4 + Tailwind 4 + Pest 5 app (despite the `laravel/laravel` name in `composer.json`). It replaces two legacy systems: **RFP** (internal payment requests) and **P2P** (vendor invoices matched against SAP POs/GRs). One Filament panel, id `hub`, at `/hub`.

The Boost block at the bottom of this file is regenerated by `boost:update` (runs on `composer install`). Keep project notes above it — Boost only rewrites the `<laravel-boost-guidelines>` block in place.

## Read this first
- `docs/README.md` is the index; read the doc for your area before coding. `TECH_STACK.md` lists installed packages/versions — verify with `composer show --direct` rather than trusting prose.
- Approval flows are **strict specs**: `docs/03-rfp-approval-flow.md` and `docs/04-p2p-flow.md`. Status transitions must match exactly, and every transition needs a test.
- `docs/07-decisions.md` (settled decisions — don't re-litigate) and `docs/08-open-questions.md` (subject to change) explain *why* the schema/flow look the way they do.
- `../p2p` and `../rfp-portal` are **read-only references**. Use them as a behaviour spec only — they run Filament 3/4 and Livewire 3, so their APIs do not apply here. Never edit them, never copy code as-is.
- Skills for Filament, Livewire, Pest, Pulse and Tailwind are under `.agents/skills/` (mirrored in `.claude/skills/`).

## Commands
- Served by Laravel Herd at `https://ramcarspendflow.test` (panel `/hub`). Do **not** run `php artisan serve`.
- Tests: `php artisan test --compact`; narrow with a file path or `--filter=name`. Feature tests live in `tests/Feature/<Area>/`.
- Test DB is in-memory SQLite (`phpunit.xml`). `RefreshDatabase` is **not** global — each feature test file opts in with `pest()->use(RefreshDatabase::class);`.
- Style: `vendor/bin/pint --dirty --format agent` after editing PHP; `vendor/bin/pint` before committing.
- Frontend: `npm run dev` (or `composer run dev`); `npm run build` for the production bundle.
- Seed: `php artisan db:seed`; `DemoMasterDataSeeder` is re-runnable, `RoleAndUserSeeder` **truncates** users/roles. Demo password `TestPass123!` (see `docs/02-roles-and-users.md`).

## Git & branches
- Branch naming: `system/type/description`, e.g. `p2p/docs/initial-documentation` (`system` = p2p/rfp/hub, `type` = feat/docs/fix, then a short description).
- P2P work items live as GitHub issues on `regideon/ramcarspendflow`, one epic per phase with sub-issues; label each `P2P`, `RFP`, both (shared/unified), or neither (new). See `docs/p2p/gh-issues/`.

## Conventions that differ from framework defaults
- Group code by module: `app/Models/Rfp/*`, `app/Filament/Resources/Rfps/*`, RFP seeders in `database/seeders/Rfp/`. Shared pieces (users, roles, notifications, approval engine) stay at the top level. Enums live in `app/Enums`.
- Reference roles through the `RoleName` enum (`RoleName::Admin`), never string literals. Adding a role = adding an enum case; the seeder creates it.
- Resolve approvers from the approval matrix (`ApprovalRule::findFor`), never hard-code a chain.
- **Migrations: new files only.** Never edit a migration that may have already run anywhere.
- Money: `decimal` columns only, never floats; approval thresholds compare the **PHP** amount.
- Every status change runs inside `DB::transaction` with a row lock on the record (prevents double approval).
- Long-running work (SAP calls, mail, PDFs) goes on the queue — nothing synchronous in a request.
- Master data is deactivated, never deleted.
- When behaviour changes, add/update the user-facing Knowledge Base article (`resources/knowledge-base/{slug}.md`, front-matter driven). It is part of the definition of done — see `docs/06-development-guide.md` §6 for the full checklist.

## Current state
- Phase 1 (master data + 21 unified roles) done; **Phase 2 (RFP) in progress** — the RFP request form (2.1) ships; the approval engine, approvals resource, and P2P are not built yet.
- **No SAP integration yet.** Wherever SAP data is needed, use generic demo data (`DemoMasterDataSeeder`).
